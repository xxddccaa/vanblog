VanBlog 自带原生评论系统。评论的存储、审核、通知都由 `server` 直接处理，没有独立的评论容器，也不需要单独配置数据库。

它取代了旧版本集成的 Waline。旧的 Waline 评论不会迁移，详见文末的 [暂不支持](#暂不支持)。

## 开启评论

在后台 `站点管理/系统设置/站点配置/高级设置` 中把「是否开启评论系统」设为「开启」，前台才会显示评论区。设为「关闭」后，前台不再显示评论区，公开评论接口也会拒绝请求。

评论区出现在这些页面：

- 文章页
- 友情链接页
- 关于页

动态页没有评论区。

下面这些文章不开放评论，既不显示评论区，也不能通过接口读取或发表评论：

- 加密文章
- 私有分类下的文章
- 隐藏文章（开启了「是否允许通过 URL 打开隐藏的文章」时除外）

评论按文章 ID 归属，修改文章路径（slug）不会让评论丢失或分家。

## 前台功能

- **楼中楼**：顶层评论分页显示，回复按楼层归在顶层评论下面，显示为「回复 @某人」。可以按最新、最早、最热排序。
- **Markdown**：支持 Markdown，带实时预览和字数统计。为了安全，评论里的 Markdown 比文章更严格：不解析 HTML，不渲染 Mermaid 等图表，去掉 iframe、音视频等嵌入内容；链接只允许 http、https 和 mailto，图片只允许 http、https 或站内地址。
- **表情**：内置 Unicode 表情面板，不加载外部资源。
- **图片上传**：可以点击按钮、拖拽或粘贴上传，详见 [图片上传](#图片上传)。博主可以在评论设置里关闭访客上传。
- **点赞**：可以取消。同一浏览器对同一条评论只算一次。
- **置顶**：博主可以在后台置顶评论，只对顶层评论生效，前台会显示「置顶」标识。
- **博主标识**：博主在同一域名下登录后台后，前台评论框会显示「以博主身份发言」，发出的评论带「博主」标识，无需审核。
- **头像**：用昵称首字母生成，颜色由昵称决定。不使用 Gravatar，不会公开邮箱的哈希。
- **访客信息**：评论下方可以显示访客的归属地（国内到省，国外到国家）、浏览器和操作系统。三项在评论设置里可以分别关闭。归属地由内置的离线 IP 库解析，不访问外部服务。
- **访客资料**：昵称可以留空，留空时显示为「匿名」；邮箱选填（可设为必填），只用于回复通知，从不公开；网址只接受 http 或 https。勾选「记住我的信息」后，资料保存在浏览器本地。
- **深链接**：`#comment-<id>` 可以定位并高亮对应评论；指向第一页以外的评论时，目前还定位不到。

访客的完整 IP、User-Agent 和邮箱只在后台可见，公开接口从不返回这些字段。

开启 `站点管理/系统设置/前台屏蔽` 后，公开接口返回的评论内容同样会按规则替换，后台看到的仍是原文。

评论被软删除后，如果下面还有公开的回复，会显示为「该评论已删除」占位；没有回复则直接不显示。

## 审核

### 审核策略

在评论设置里可以选择三种审核策略：

| 策略 | 说明 |
| --- | --- |
| 全部先审 | 所有访客评论都要审核通过后才显示 |
| 只审可疑（默认） | 可疑评论进入待审核，其余直接显示 |
| 不审 | 除命中违禁词的评论外，全部直接显示 |

博主本人发表的评论不需要审核。

「只审可疑」模式下，满足下面任意一条的评论算作可疑：

- 内容里有 3 个及以上链接
- 内容里有连续 16 个及以上相同的字符
- 内容里有访客上传的图片

### 违禁词

违禁词每行一个，不区分大小写，最多 500 个，每个不超过 64 个字符。昵称、邮箱、网址或内容里含有违禁词的评论会直接进入「垃圾」，在任何审核策略下都不会公开。

访客看不出自己的评论被判为垃圾：前台只会提示「评论已提交，审核后显示」。

### 回复的可见性

- 父评论不是「已通过」时，它下面的回复一律不公开。
- 把一条评论移回待审或标为垃圾时，它下面所有未删除的回复会一起变成同样的状态。
- 回复要在父评论通过（或父评论已删除）之后才能通过审核。

## 防垃圾

### 限流

访客按 IP 计数，IPv6 地址按 /64 网段合并计数。超过限额时接口返回 `429`，并带上 `retryAfterSeconds`。

| 操作 | 限额 |
| --- | --- |
| 发表评论 | 每个访客 10 分钟 5 条、每天 30 条；每个页面每小时 30 条；全站每小时 300 条 |
| 点赞 | 每个访客 10 分钟 60 次 |
| 上传图片 | 每个访客每小时 10 张、每天 30 张；全站每小时 200 张；同时最多处理 2 张 |
| 读取评论列表和评论数 | 每个访客每分钟 120 次（前台服务端渲染发出的内部请求不计） |

博主登录状态下发表评论和上传图片不受这些限额约束。

### 其他措施

- **蜜罐字段**：评论表单里有一个对访客隐藏的字段。机器人填了它，评论会被静默丢弃，但接口照常返回「待审核」，不会暴露原因。
- **重复提交**：同一页面、同一父评论下，相同昵称和相同内容的评论 10 分钟内只能提交一次，重复提交返回 `409`。
- **同源校验**：发表、点赞、上传图片都必须从本站页面发起。跨站请求会被拒绝（`403`），发表和点赞还要求请求体是 JSON。
- **长度和格式**：内容默认最多 5000 字（可在设置里调到 20000）；昵称最多 32 字；邮箱最多 128 字并校验格式；网址最多 200 字，只允许 http/https，不能带用户名密码；内容里不能有控制字符。

### 全站隐私

开启 `全站隐私设置` 后，评论接口和其他公开接口一样，对未登录的访客返回 `401`，评论内容不会外泄。

## 图片上传

- 只接受 PNG、JPEG、WebP、GIF，按文件内容判断类型，SVG 一律拒绝；GIF 只保留第一帧。
- 单张不超过 5 MB，像素数也有上限。
- 图片会重新编码为 WebP 并去掉元数据，保存在静态目录的 `img/comment/` 下，访问地址形如 `/static/img/comment/<sha256>.webp`。
- 每天凌晨 3:30 清理一次：上传超过 24 小时、仍没有被任何评论（包括已软删除的评论）引用的图片会被删除。

## 通知

在后台 `站点管理/系统设置/评论设置` 的「通知设置」里配置。邮件和 Webhook 里的站点名称、页面链接取自站点配置；没有填写网站地址时，邮件里不带链接。

### 邮件

先填写 SMTP 设置并打开「启用邮件通知」：

| 设置项 | 说明 |
| --- | --- |
| SMTP 主机 | 例如 `smtp.qq.com` |
| SMTP 端口 | 默认 `465` |
| SSL/TLS | 465 端口一般开启；587 端口（STARTTLS）请关闭 |
| SMTP 用户名 | 通常是邮箱地址 |
| SMTP 密码 | 只写不读：保存后接口和页面都不会再显示 |
| 发件人名称 | 可选，留空使用站点名称 |
| 发件人邮箱 | 留空使用 SMTP 用户名 |

很多邮件服务商默认关闭 SMTP，需要先在服务商的设置里开启，并使用单独生成的授权码作为 SMTP 密码。以 QQ 邮箱为例，发件人邮箱需要和 SMTP 用户名一致，否则可能报 `501 Mail from address must be same as authorization user`。

保存后可以点「发送测试邮件」检查配置。测试邮件使用已保存的设置，即使「启用邮件通知」还没打开也会发送。

邮件分两类：

- **新评论通知博主**：访客发表评论后发给「博主邮箱」，邮件里注明评论是否待审核或疑似垃圾，并附评论链接和后台管理链接。博主自己的评论不通知；评论之后被审核通过时也不会再发一次。
- **回复通知被回复者**：评论被回复、且回复已通过审核时，发给被回复者留下的邮箱。回复当时待审核的，在审核通过时补发。以下情况不发：被回复者没留邮箱、被回复的是博主、回复者和被回复者邮箱相同、被回复者邮箱就是已经收到新评论通知的博主邮箱。每条回复最多发一封。

「博主邮箱」同时作为 RSS 中的作者邮箱；没填时 RSS 使用 `EMAIL` 环境变量。

为了防止有人借回复功能给任意邮箱刷信，发送有每日上限：每个收件人每天最多 10 封，全站每天最多 200 封。超出后当天不再发送，只在服务端日志里记录。

### Webhook

在「Webhook 地址」填一个 http 或 https 地址后，有新评论或评论审核通过时，`server` 会向它发送一条 `POST` 请求（`Content-Type: application/json`，`User-Agent: VanBlog-Comment-Webhook`）。超时 5 秒，不重试，不跟随重定向。

请求体示例：

```json
{
  "event": "comment.created",
  "site": { "name": "我的博客", "url": "https://blog.example.com" },
  "target": {
    "key": "post:12",
    "type": "post",
    "id": "12",
    "title": "Hello World",
    "url": "/post/hello-world"
  },
  "comment": {
    "id": 34,
    "parentId": null,
    "rootId": null,
    "nick": "访客",
    "link": "https://example.com/",
    "isAdmin": false,
    "status": "pending",
    "excerpt": "评论内容摘录",
    "createdAt": "2026-11-17T08:00:00.000Z"
  }
}
```

- `event`：`comment.created`（新评论，任何初始状态，包括待审核和垃圾）或 `comment.approved`（待审核或垃圾评论被审核通过）
- `target.key`：`post:<文章 ID>`、`page:link` 或 `page:about`
- `comment.excerpt`：评论 Markdown 原文的前 500 个字符

请求体里没有邮箱、IP 和 User-Agent。

### 流水线事件

评论系统会触发两个被动的 [流水线](./pipeline.md) 事件，脚本收到的 `input` 和 Webhook 请求体相同：

- `afterCommentCreate`（新评论之后）
- `afterCommentApprove`（评论审核通过之后）

## 后台管理

### 评论管理

后台 `站点管理/评论管理` 只对超级管理员开放。侧边菜单上会显示待审核数量的角标，仪表盘上也有「最近评论」和待审核数量。

- 按状态分页查看：全部、待审核、已通过、垃圾、已删除
- 搜索内容、昵称、邮箱或 IP，也可以按文章筛选
- 单条操作：通过、标为垃圾、移回待审、置顶或取消置顶（仅顶层评论）、编辑内容、以博主身份回复、删除、彻底删除
- 已删除的评论可以恢复到待审核，或者彻底删除
- 批量操作：通过、标为垃圾、删除、彻底删除
- 展开一行可以看到完整内容、回复对象、所在页面、邮箱、网址、完整 IP、归属地、浏览器、操作系统和 User-Agent

「删除」是软删除，评论进入「已删除」，可以恢复。「彻底删除」会连同这条评论下的所有回复和点赞一起删掉，无法恢复。

以博主身份回复一条待审核的评论时，会先把这条评论审核通过；垃圾评论和已删除的评论不能回复。

### 评论设置

后台 `站点管理/系统设置/评论设置` 包含两部分。

评论设置：

| 设置项 | 默认值 | 说明 |
| --- | --- | --- |
| 审核策略 | 只审可疑 | 见 [审核策略](#审核策略) |
| 违禁词 | 空 | 见 [违禁词](#违禁词) |
| 每页条数 | 10 | 前台每页显示的顶层评论数，范围 5 到 50 |
| 字数上限 | 5000 | 单条评论的最大字符数，最多 20000 |
| 访客上传图片 | 开启 | 关闭后访客不能在评论中上传图片 |
| 邮箱必填 | 关闭 | 开启后访客必须填写邮箱才能评论 |
| 显示归属地 / 显示浏览器 / 显示操作系统 | 开启 | 分别控制前台是否显示这三项 |

通知设置：见 [通知](#通知)。

## 缓存

- 评论列表和评论数接口对所有访客返回相同内容，响应头为 `Cache-Control: public, max-age=0, s-maxage=30`：浏览器不缓存，CDN 最多缓存 30 秒。评论公开状态变化时，`server` 会清掉对应文章的评论数缓存；配置了 Cloudflare 缓存清理时，还会按页面清理 CDN 上的评论缓存。
- 当前访客的博主身份（`/identity`）和点赞记录（`/liked`）因人而异，一律 `no-store`。
- 发表、点赞、上传等写请求从不缓存。
- 刚发表的评论会先直接插入到当前页面，不用等缓存过期。

详见 [Cloudflare 缓存说明](../cloudflare-cache.md)。

## 备份

评论和点赞保存在主数据库里，会随后台的备份导出，导入包含评论的备份时一起恢复，清空站点数据时也会一起清空。详见 [备份与恢复](../guide/backup.md)。

## 暂不支持

- 访客注册、登录和第三方 OAuth 登录
- 访客编辑或删除自己的评论
- Waline 数据迁移：旧的 Waline 评论不会导入新系统。已有部署里的 `waline` 数据库原样保留，新版本不再创建或读写它，也不会删除它
