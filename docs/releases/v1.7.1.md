# v1.7.1

`v1.7.1` 是一次功能版本，为前台引入可配置的字体设置：支持维持原样、内置预设、自定义上传三种模式，预设按中文/英文分别选择内置字体，全部按需加载。

如果只用一句话概括：

> `v1.7.1` 让站长在后台一处切换前台字体：中文可选霞鹜文楷 / MiSans / 思源宋体，英文可选 EB Garamond / Inter / JetBrains Mono，中英自由组合、未选一侧维持系统字体，也可上传自己的字体；内置字体经子集化后只按页面用字按需下载。

## 本版摘要

- 后台「系统设置 → 字体设置」新增字体配置页，三种模式：
  - **维持原样**：前台不注入任何字体规则，与旧版完全一致（默认）
  - **内置预设**：中文、英文各一个下拉，从内置字体里挑选并自由组合
  - **自定义上传**：上传 woff2 / woff / ttf / otf 字体文件，自定义 `font-family` 栈
- 内置 6 种可自托管字体（均为 OFL / 免费商用）：
  - 中文：霞鹜文楷、MiSans、思源宋体
  - 英文/数字：EB Garamond、Inter、JetBrains Mono
  - 每侧都含「系统默认（不下载）」选项，未选一侧回落到系统字体
- 作用范围可选「仅文章正文」或「全站」
- 内置字体经 cn-font-split 子集化为 unicode-range woff2 分片，前台只按当前页面用到的字下载对应分片；预设字体表与上传字体均长期 immutable 缓存，翻页不再重复请求
- 新增字体上传端点 `POST /api/admin/font/upload`：扩展名白名单 + 文件魔数校验，拒绝非字体文件
- `GET/PUT /api/admin/setting/font` 读写字体设置；`GET /api/public/meta` 在非「维持原样」时下发字体设置供前台注入

## 相比 v1.7.0 的变化

如果你已经在使用 `v1.7.0`，这一版最直接的变化是：

- 后台系统设置多出「字体设置」标签页
- 默认仍是「维持原样」，不改动任何现有站点的观感；只有主动选择预设或上传字体后前台才生效
- website 镜像体积因内置 6 种子集化字体略有增加（约 23MB 静态资源）

## 部署注意事项

- 字体功能全部包含在 `website` 与 `server` 镜像内，无新增伴生容器、无新增环境变量
- 自定义上传的字体走本地静态存储（`/static/font/`），图床（picgo）仅用于图片，字体固定本地存储
- 内置预设字体随 `website` 镜像发布，无需额外挂载

如果你使用锁版镜像部署：

```env
VANBLOG_DOCKER_REPO=kevinchina/deeplearning
VANBLOG_RELEASE_SUFFIX=v1.7.1-<image-id>
```

## 升级建议

升级到 `v1.7.1` 后，建议重点验证：

1. 后台「系统设置 → 字体设置」默认为「维持原样」，前台字体与升级前一致
2. 切到「内置预设」，中文选霞鹜文楷、英文选 EB Garamond，保存后前台文章正文字体变化，且只下载用到的分片
3. 尝试中英不同组合（如 MiSans + JetBrains Mono），确认中文命中中文字体、英文/数字命中英文字体
4. 任一侧选「系统默认」，确认该语言恢复系统字体、不产生字体下载请求
5. 「自定义上传」上传一份 woff2 字体并填 `font-family` 栈，前台正确加载；上传非字体文件被拒
6. 切回「维持原样」，确认前台不再注入任何字体规则

## 回滚方法

如果线上想回滚到上一版，只需要把：

```env
VANBLOG_RELEASE_SUFFIX=v1.7.1-<image-id>
```

改回上一版的 release suffix，然后重新执行：

```bash
docker compose -f docker-compose.image.yml up -d
```

字体设置存于数据库，回滚镜像不会丢失设置；旧版镜像不读取该设置，前台自动恢复为默认字体。
