# v2.0.0

> 发布日期：2026-11-18

这是一个大版本：评论改为 `server` 内置的原生评论系统，同时彻底移除 Waline。核心镜像从 5 个减为 4 个。**升级必须换用新版本的 compose 文件**，旧的 Waline 评论不会迁移，请先阅读下面的「升级步骤」和「不兼容变更」。

## 重点

- **原生评论系统**：评论的存储、审核、通知都由 `server` 处理，前台评论区和后台管理页全部重写。
- **移除 Waline**：不再有 `waline` 服务、`vanblog-waline-*` 镜像和 `packages/waline`；all-in-one 容器里也不再启动 Waline。
- **4 个核心镜像**：拆分部署只发布 `caddy`、`server`、`website`、`admin`，拓扑变为 6 个核心服务（另加 `kroki`）。

## 原生评论

完整说明见 [评论](../features/comment.md)。

- **覆盖页面**：文章页、友情链接页、关于页；动态页没有评论区。加密文章、私有分类下的文章、隐藏文章（未开启「是否允许通过 URL 打开隐藏的文章」时）不开放评论。
- **前台**：楼中楼、最新 / 最早 / 最热排序、Markdown 与实时预览、内置表情、图片上传（点击、拖拽、粘贴）、点赞、置顶、`#comment-<id>` 深链接、暗色模式与移动端适配。
- **身份与隐私**：博主登录后台后在前台以「博主」身份发言，无需审核；头像用昵称首字母生成，不使用 Gravatar；可分别显示访客的归属地、浏览器和操作系统，完整 IP、User-Agent 和邮箱只在后台可见。
- **审核**：全部先审 / 只审可疑（默认）/ 不审三种策略，外加违禁词。「只审可疑」会把含 3 个及以上链接、连续 16 个及以上相同字符或任何图片（包括外链图片）的评论放进待审核。
- **防垃圾**：按访客 IP（IPv6 按 /64）限流，蜜罐字段，10 分钟内重复内容拒绝，写请求必须同源。
- **通知**：SMTP 邮件通知博主和被回复者，每个收件人每天最多 10 封；博主通知与回复通知各有每日 200 封的全站额度，互不挤占。访客回复的通知邮件只包含链接、不引用回复内容，博主回复才会引用原文。后台可发测试邮件；Webhook 在新评论和审核通过时推送 JSON，请求体不含邮箱、IP 和 UA；新增流水线事件 `afterCommentCreate`、`afterCommentApprove`。
- **后台**：`站点管理/评论管理`（仅超级管理员）支持按状态查看、搜索、按文章筛选、单条和批量审核、置顶、编辑、以博主身份回复、软删除与彻底删除；侧边菜单显示待审核角标，仪表盘新增「最近评论」；`系统设置/评论设置` 替代原来的 Waline 设置。
- **缓存**：评论列表和评论数浏览器不缓存、CDN 最多缓存 30 秒；博主身份和点赞记录 `no-store`；写请求从不缓存。
- **备份**：评论和点赞纳入后台备份导出、导入与清空站点数据。

## 评论系统的安全设计

评论是全站最大的匿名写入口，发布前做过一轮独立的安全审查，以下问题已在本版本内修复：

- **图片上传**：只接受 PNG、JPEG、WebP、GIF，按文件内容识别类型，全部重新编码为 WebP 并去除元数据；SVG 一律拒绝。GIF 在解码前会校验首帧尺寸，拒绝首帧超出画布的文件，防止极小的文件让服务端长时间卡住。
- **通知滥用**：访客回复的通知邮件不再引用回复内容，避免借站点邮箱向任意地址发送他人编写的内容。
- **额度消耗**：全站与单页的评论额度、全站图片额度只在请求通过校验后才扣减，无效请求无法耗尽他人额度。
- **缓存**：评论列表读取失败（例如触发限流）时改为不缓存，CDN 不会把一次错误响应展示给所有访客。
- **渲染**：评论 Markdown 不解析原始 HTML，链接只允许 http/https/mailto 并带 `nofollow ugc`，公式渲染关闭信任模式，评论内容的绘制限制在评论框内。
- 套了 Cloudflare 或其他外层反代时，服务端看到的是代理地址，所有访客共用一份评论限流额度，评论的归属地也会显示为代理所在地。个人博客一般够用；需要按真实访客区分时，在 Caddy 中配置可信代理。

## 不兼容变更

- 移除 `waline` 服务、`vanblog-waline-*` 镜像和 `packages/waline`。本版本起不再发布新的 `vanblog-waline-*` 标签。
- Waline 的路由全部移除：`/api/comment*`、`/api/ui*` 现在由 `server` 处理并返回 `404`；`/comment*`、`/ui*` 等其余旧路径落到前台。后台不再内嵌 Waline 管理页。
- **不迁移 Waline 评论**。旧评论不会出现在新的评论系统里；已有部署里的 `waline` 数据库原样保留，新版本不再创建、读写或删除它。
- 旧的 Waline 设置（包括 SMTP 和博主邮箱）不会带到新的「评论设置」，需要重新填写。在填写「博主邮箱」之前，RSS 的作者邮箱使用 `EMAIL` 环境变量。
- 评论管理只对超级管理员开放，协作者看不到。
- 不支持访客注册、登录和第三方 OAuth，也不支持访客编辑或删除自己的评论。
- 站点共享密钥改名：`WALINE_JWT_TOKEN` → `VANBLOG_SHARED_SECRET`，密钥文件 `waline.jwt` → `vanblog-shared.secret`。旧变量名和旧文件仍会被读取，见下文。
- 不再使用的变量：`VAN_BLOG_WALINE_DB`、`VAN_BLOG_WALINE_DATABASE_URL`、`VAN_BLOG_WALINE_API_URL`、`VANBLOG_WALINE_CONTROL_URL`。旧 `.env` 里留着也会被忽略。

## 行为变化

- 开启「全站隐私设置」后，评论接口和其他公开接口一样对未登录访客返回 `401`。`v1.9.1` 中 Waline 不在拦截范围内的问题随之消失。
- 开启「前台屏蔽」后，公开接口返回的评论内容同样会按规则替换。
- 文章卡片和文章页的评论数改由原生评论统计；不开放评论的文章计为 0。
- 发表评论、点赞和上传评论图片会校验 `Origin` / `Referer` 与 `Host` 是否一致。在外层再套反向代理时，必须原样传递 `Host` 请求头，否则这些请求会返回 `403`，见 [反代](../reference/reverse-proxy.md)。

## 升级步骤

1. **备份**：在后台 `站点管理/系统设置/备份恢复` 导出一次，并备份宿主机的 `data/`、`log/`、`secrets/`、`caddy/` 目录。如果还想保留 Waline 的旧评论，自行备份 PostgreSQL 里的 `waline` 库。
2. **换用新的 compose 文件**：从仓库取新版本的 `docker-compose.image.yml`、`docker-compose.latest.yml` 或 `docker-compose.all-in-one*.yml`，替换旧文件。旧的 `docker-compose.image.yml` 还引用 `vanblog-waline-*` 镜像，用它拉取新版本会失败。
3. **`.env` 不用改**：锁版部署只需按惯例把 `VANBLOG_RELEASE_SUFFIX` 改成新版本。`WALINE_JWT_TOKEN` 仍会被读取；没有设置时，日志目录里已有的 `waline.jwt` 会在首次启动时被沿用到新的 `vanblog-shared.secret`，旧文件不会被修改，所以共享密钥保持不变。
4. **拉取并启动**。拆分部署换用新 compose 后，旧的 `waline` 容器会变成孤儿容器，可以加 `--remove-orphans` 一起删掉：

   ```bash
   docker compose -f docker-compose.image.yml pull
   docker compose -f docker-compose.image.yml up -d --remove-orphans
   ```

5. **配置评论**：在 `站点管理/系统设置/站点配置/高级设置` 确认「是否开启评论系统」为「开启」，然后在 `站点管理/系统设置/评论设置` 检查审核策略（默认「只审可疑」），重新填写博主邮箱、SMTP 和 Webhook，并发送一封测试邮件。
6. **Cloudflare**：删除以前为 Waline 添加的绕过缓存规则（`/api/comment*`、`/comment*`、`/ui*`、`/user*`、`/token*`、`/db*`、`/oauth*`）。可以把 `/api/public/comment/identity`、`/api/public/comment/liked` 加入绕过规则，见 [Cloudflare 缓存说明](../cloudflare-cache.md)。

## 升级提示

- 旧版本导出的加密备份照样能解密导入：解密时会依次尝试独立的备份加密密钥和站点共享密钥（新名字和旧名字 `WALINE_JWT_TOKEN` 都会尝试）。备份加密密钥的路径和生成方式没有变化。
- 本版本不迁移评论数据，也不删除 `waline` 数据库；是否保留它由维护者自行决定。
- 继续使用旧的 `docker-compose.latest.yml` 时还会拉起旧的 `waline` 容器，但它已不再被使用。请换用新文件。
- 需要回滚到 `v1.9.x` 时，要同时换回该版本的 compose 文件（拆分部署需要其中的 `waline` 服务）。

## 发布与部署

- 发布 `caddy`、`server`、`website`、`admin` 及 `all-in-one` 五类镜像，不再发布 `waline`。
- 每类镜像同步不可变版本标签、版本别名和 `latest`，生产使用带提交 ID 的版本标签。
