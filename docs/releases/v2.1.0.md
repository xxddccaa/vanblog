# v2.1.0

> 发布日期：2026-11-18

`v2.1.0` 移除了 Kroki 图表渲染服务，部署从此少一个容器、少一个约 4GB 的镜像；同时修正了评论开关的默认值。Mermaid 和 WaveDrom 图表照常显示，不受影响。

## 不兼容变更

- **移除 Kroki**：不再有 `kroki` 服务和 `yuzutech/kroki` 镜像，也不再读取 `VANBLOG_KROKI_URL`。原先由 Kroki 渲染的图表类型——PlantUML、Graphviz（dot）、D2、Vega-Lite、ditaa、nomnoml、svgbob、ERD、blockdiag 系列等——现在都按普通代码块显示，带复制、换行、折叠工具栏。
- **移除接口 `POST /api/public/diagram/render`**，现在返回 `404`。
- **后台导出 PDF** 不再把上述代码块转成图表；WaveDrom 代码块在导出的 PDF 里也按代码显示。站点前台和后台编辑器里的 WaveDrom 照常渲染。
- **RSS** 里的这些代码块同样按普通代码块输出。

不受影响的：

- **Mermaid**：在读者浏览器里渲染，前台、后台编辑器和 PDF 导出都照常显示。
- **WaveDrom**：前台和后台编辑器照常渲染。

## 修复

- **评论开关默认关闭**：「是否开启评论系统」从未保存过时，服务端此前会当作开启，与前台、后台「默认关闭」的显示不一致；现在服务端也一律当作关闭，只有明确开启后评论接口才可用。

## 升级步骤

1. **备份**：照常导出一次备份，并备份宿主机的 `data/`、`log/`、`secrets/`、`caddy/` 目录。
2. **换用新的 compose 文件**，或在现有 compose 里删掉 `kroki` 服务和 `VANBLOG_KROKI_URL` 这一行。拆分部署还需从 `NO_PROXY` / `no_proxy` 里去掉 `kroki`。
3. **启动时带上 `--remove-orphans`**，把遗留的 kroki 容器一起删掉：

   ```bash
   docker compose -f docker-compose.all-in-one.latest.yml up -d --remove-orphans
   ```

4. **（可选）删除镜像** 释放约 4GB 磁盘：`docker rmi yuzutech/kroki`。
5. **检查评论开关**：如果站点需要评论，确认后台「站点配置 / 高级设置」里「是否开启评论系统」已设为「开启」。

## 发布与部署

- 发布 `caddy`、`server`、`website`、`admin` 及 `all-in-one` 五类镜像。
- 每类镜像同步不可变版本标签、版本别名和 `latest`，生产使用带提交 ID 的版本标签。
