# v1.7.6

`v1.7.6` 是一次前台暗色显示的修复版本，修掉 `v1.7.5` 引入的一个回归：暗色模式下首页文章卡片预览的文字偏淡（很淡的灰白），需要点进文章再返回才恢复正常亮色。

如果只用一句话概括：

> `v1.7.5` 让首页卡片改用与文章页同款的 Markdown 渲染（`.markdown-body`），但首页没有注入决定暗色文字色的 markdown 主题 CSS，导致暗色下卡片文字继承了偏淡的灰色；`v1.7.6` 给首页及同类页面补齐主题 CSS 注入，首屏即为正常亮色。

## 问题根因

- `.markdown-body` 的暗色文字色来自 markdown 主题 CSS（如 `vanblog-graphite-dark-only.css`），该样式由 `Layout` 在 `includeMarkdownThemeHead` 为真时于客户端注入。
- 此前只有文章详情页与「关于」页开启了该开关；首页、动态、友链页没有开启。
- `v1.7.5` 把首页卡片预览从纯文本（依赖 Tailwind `dark:text-dark`，首屏即正确）改为 `.markdown-body`（依赖主题 CSS），于是暴露出「暗色文字偏淡」的问题。软导航到文章页会注入该主题 `<link>`，返回首页时样式残留，所以会出现「返回后变正常」的现象。

## 本版修复

- 为以下使用 `<Markdown>` 的前台页面补齐 `includeMarkdownThemeHead`，使 markdown 主题 CSS 在这些页面也注入，暗色文字首屏即为正常亮色：
  - 首页（文章卡片预览）
  - 动态页
  - 友链页
- 纯前端改动，不改后端接口、不改文章内容、不影响亮色模式与既有文章页表现。

## 升级建议

升级到 `v1.7.6` 后，在暗色模式下重点验证：

1. 首页文章卡片预览文字为正常亮色，**无需**点进文章再返回。
2. 动态页、友链页的 Markdown 文字同样为正常亮色。
3. 亮色模式与文章详情页表现保持不变。

## 回滚方法

纯前台改动，不涉及数据与配置迁移。把 release suffix 改回上一版并重新 `docker compose -f docker-compose.image.yml up -d` 即可。

锁版镜像部署：

```env
VANBLOG_DOCKER_REPO=kevinchina/deeplearning
VANBLOG_RELEASE_SUFFIX=v1.7.6-<image-id>
```
