# v1.8.0

`v1.8.0` 是一次**安全整改专版**：在 `v1.7.6` 基线上完成了一轮完整的静态安全审查中记录的 17 项发现的整改，并同步推进了运行时与依赖的一次较大升级（Node 22、Next 16、React 19 等）。

如果只用一句话概括：

> 把「文章 Markdown / SVG 可执行内容」这条最高优先级的持久型 XSS 链路彻底堵死，并围绕它补齐 CSP、限流、鉴权 fail-closed、出站 SSRF 校验、密码与 Token 加固、备份加密、容器降权等纵深防御；同时完成 Node 22 / Next 16 / 依赖大版本升级。

本版含依赖大版本升级与备份格式变更，属于 minor 级别发布，升级前请阅读下方「升级注意」。

## 主要安全整改

- **Markdown / RSS / 图表 SVG XSS（Critical）**：前台、管理端、服务端 Markdown 统一走白名单清洗，禁止 `script`、事件属性、`javascript:`、危险 CSS；iframe 不再放行；Kroki/WaveDrom SVG 经 DOMPurify 清洗或以不可执行图片方式内嵌；RSS 用维护中的 `@vscode/markdown-it-katex` 并对输出做 `sanitize-html` 白名单（放行 KaTeX 所需的 MathML 标签与安全布局样式）。
- **CSP 与安全响应头**：Caddy 统一下发 `nosniff`、`X-Frame-Options`、`Referrer-Policy`、`Permissions-Policy` 与默认 CSP；Next.js 前台改为**逐请求 nonce + `strict-dynamic`**，移除内联/`eval`/第三方统计脚本对 `unsafe-inline`/`unsafe-eval` 的依赖；`/swagger` 在所有公开入口统一返回 404，生产环境不再挂载 Swagger。
- **公开图表渲染接口 DoS**：独立请求体上限、Redis 原子的 IP/全局限流（跨实例）、并发信号量、上游超时、流式响应大小限制与按字节淘汰的缓存；移除无界的进程内限流 Map。
- **IPv6 边界规范化**：改用 `node:net` 与显式私网判断，只转换合法 IPv4-mapped IPv6，修复「公网 IPv6 被误判为私网」导致的初始化/恢复/debug-token/登录限流绕过。
- **出站 SSRF**：出站 URL 对 A/AAAA 逐项校验并拒绝私网/回环/链路本地地址，禁用重定向，设置超时与响应大小上限；图片下载与 AI 请求共用安全校验。
- **密码与访问控制**：管理员/协作者/受保护内容密码改用 Argon2id，兼容旧哈希并渐进迁移；文章解锁在密码验证前使用 Redis 原子计数限流；`AccessGuard` 异常与非法权限结构一律 fail-closed。
- **备份安全**：备份改为 AES-256-GCM + scrypt 派生 + 篡改检测的 `.vbe` 格式，流式写入、临时文件原子替换与 `0700/0600` 权限；加密密钥使用独立环境变量 `VANBLOG_BACKUP_ENCRYPTION_KEY`（Docker 会在缺省时生成并持久化到独立 secret 卷，**不再**从数据库内 JWT 派生），并保留对旧密钥备份的只读解密兼容。
- **备份导入并发**：改用 Redis 原子分布式锁与所有权校验，避免 check-then-set 竞态导致并发清库。
- **自动备份健壮性**：定时回调最外层 `try/catch/finally` 保证失败后继续调度，并对 `HH:mm`、保留数量做运行时校验。
- **凭证与流水线**：登录/退出事件与日志递归脱敏并限制体积；生产环境流水线默认关闭，启用需显式危险开关；子进程设置超时、内存/输出上限，以非 root UID 运行并启用 Node Permission Model 限制网络/子进程/文件访问。
- **访问统计**：布尔查询显式规范化、Referer 必须属于本站、统计更新改为数据库原子自增（`$inc` / SQL `+1`），修复计数失真、伪造与并发丢计数。
- **图表 PNG 传输**：SVG 按文本、PNG 按二进制 Buffer 读取与缓存，修复 PNG 经 UTF-8 解码损坏。
- **API Token**：默认有效期缩短为 90 天，数据库仅保存 SHA-256 摘要，完整值仅签发时返回一次。
- **容器最小权限**：split 的 server/website/waline 以非 root UID/GID 运行，最终镜像移除构建工具；Compose 启用 `no-new-privileges`、能力裁剪、PID 限制并强制数据库强密码。

> 残余项：登录/退出流水线已做纵深缓解，但仍与 server 处于同一容器，尚不等同于独立容器级强隔离——作为已知架构残余风险保留。

## 运行时与依赖

- Node 22 / pnpm 10 基线；升级 Next.js 16、React 19、Axios、Multer 等直接生产依赖。
- 移除 `image-size`（改为受限的魔数 + 自实现尺寸解析）、`markdown-it-katex`（改 `@vscode/markdown-it-katex`）、PicGo 存储适配（改为提示切换本地存储）。
- 新增 `@node-rs/argon2`、`sanitize-html`、`dompurify` 等安全相关依赖。

## 升级注意

- **备份加密密钥**：生产部署建议显式设置 `VANBLOG_BACKUP_ENCRYPTION_KEY`（≥16 字符，推荐 32 位随机）并**离机另存**；缺省时 Docker 会在 secret 卷内生成一份，丢失该卷将导致 `.vbe` 备份无法解密。旧的明文/旧密钥备份仍可只读导入。
- **备份格式**：自动/手动导出产物由 `.json` 改为加密的 `.vbe`；导入同时兼容旧 `.json`。
- **PicGo 存储停用**：若此前使用 PicGo 图床，请将存储方式切换为本地存储。
- **Swagger**：生产环境 `/swagger` 统一返回 404；如需查看 API 文档请使用非生产环境。
- **CSP**：如站点依赖外部内联脚本，请改为通过自定义脚本入口注入（已支持 nonce），避免被 CSP 拦截。

## 升级建议

升级到 `v1.8.0` 后重点验证：

1. 含 `<script>`、事件属性、`javascript:` URL、恶意 iframe/SVG 的文章在前台、管理端预览与 RSS 中均被安全清洗。
2. 数学公式（KaTeX）在前台与 RSS 中渲染正常。
3. 图表接口在大请求/高并发下有限流与超时保护。
4. 备份可正常导出为 `.vbe` 并成功导入；旧 `.json` 备份仍可导入。
5. 生产响应头包含 CSP 等安全头，`/swagger` 返回 404，容器以非 root 运行。
